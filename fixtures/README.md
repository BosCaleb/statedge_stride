# Fixtures

Fixtures contain keypoints only, never video of identifiable people.

## Keypoint fixtures (`keypoints/*.skp1.gz`)

Each file is a gzip-compressed SKP1 keypoint file (format in `packages/analysis/src/skp1.ts`).
`manifest.json` lists every fixture with where it came from, how to run it (mode, declared frame
rate, calibration, camera shift) and the gate result and metric ranges it must produce.
`fixtures.test.ts` runs them all through the pure pipeline on every CI run.

### Current fixtures: synthetic

All current fixtures are **synthetic**. They were generated by `scripts/generate-fixtures.ts`
from the synthetic gait generator (`packages/analysis/src/testing/syntheticGait.ts`); no person
was filmed and no consent is needed. They stand in for the recorded spike fixtures (spec M0
task 7) until real clips are measured on the Samsung Galaxy S23 Ultra and an iPhone.

| Fixture                | Scenario                                                   | Expected gate               |
| ---------------------- | ---------------------------------------------------------- | --------------------------- |
| `distance-ltr`         | Distance running, left to right                            | pass or conditional         |
| `distance-rtl`         | Distance running, right to left (left leg near the camera) | pass or conditional         |
| `sprint-ltr`           | Sprinting, left to right                                   | pass or conditional         |
| `sprint-rtl`           | Sprinting, right to left                                   | pass or conditional         |
| `occluded-far-leg`     | Far leg often hidden                                       | pass or conditional         |
| `camera-moved`         | Camera moved 20 px against the calibration                 | fail (`camera_stable`)      |
| `wrong-mode-30fps`     | Recorded in normal 30 fps video mode                       | fail (`fps_ok`)             |
| `wrong-frame-rate`     | Super slow-mo mix-up: cadence comes out absurd             | fail (`timebase_plausible`) |
| `athlete-stops`        | Athlete stops part way through                             | fail (`steady_direction`)   |
| `body-out-of-frame`    | Legs leave the bottom of the frame                         | fail (`body_visible`)       |
| `side-labels-mismatch` | Far side clearer than the near side                        | conditional (`side_labels`) |

Regenerate with `pnpm tsx scripts/generate-fixtures.ts`.

### Adding recorded fixtures from the spike

1. Export the keypoints from the spike page (`/dev/spike`, "Download keypoints"). The export is
   the raw SKP1 file; gzip it (`gzip -9 name.skp1`) into `keypoints/`.
2. Add an entry to `manifest.json` with `"source": "recorded"` and a `consent` object naming the
   owner of the source clip and the date they agreed to its use. The test refuses a recorded
   fixture without it.
3. Record the expected gate result and generous metric ranges from the spike measurements.
4. Delete the source video once the keypoints are exported. Never commit it.

## Test clips (`clips/`)

`clips/probe/` holds tiny synthetic test-pattern clips (no people) for the container probe
tests: H.264 with the moov box before and after the media, VP9, HEVC, a re-timed 30 fps file and
a rotated file. `clips/synthetic-run-240fps.mp4` and `clips/synthetic-calibration-240fps.mp4` are
rendered stick-figure clips for the end-to-end tests. See `scripts/generate-test-clips.ts`.
