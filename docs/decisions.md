# Decisions and deviations from the specification

Every place where the build differs from, or adds to, `docs/spec.md`, with the reason. Entries marked **Needs approval** add a dependency or service the specification does not name, or change a stated choice; they stay as built until StatEdge says otherwise.

## Stack and tooling

| #   | Decision                                                                                           | Reason                                                                                                                                                                                                                                    |
| --- | -------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1  | Node.js 22 LTS everywhere (`.nvmrc`, Functions runtime)                                            | The spec says 20 or later. Node 20 reached end of life in April 2026; 22 is the newest version the Linux Consumption plan runs                                                                                                            |
| D2  | React Router 7                                                                                     | React Router 8 needs React 19, and the spec fixes React 18                                                                                                                                                                                |
| D3  | Current major versions of TypeScript (6), Vite (8), Vitest (5), ESLint (10), Playwright (1.63)     | No reason to start a new repository on old majors                                                                                                                                                                                         |
| D4  | **Needs approval.** esbuild bundles the API (`apps/api/scripts/build.ts`)                          | The spec says `tsc` and Core Tools. The shared packages export TypeScript sources, which the Functions runtime cannot load; one bundle also deploys without `node_modules`. esbuild is MIT and already in the tree as a dependency of tsx |
| D5  | `scripts/` is a workspace package (`@stride/scripts`)                                              | So that the staff and tooling scripts declare their own dependencies (zod, mssql)                                                                                                                                                         |
| D6  | `pnpm dev` falls back to a small Node server for the API when Core Tools (`func`) is not installed | Developers can run the full stack with Docker and Node only. With `func` on the PATH it uses the real Functions host and Azurite, as the spec describes                                                                                   |
| D7  | Removed the Application Insights Node SDK from the API                                             | The Functions host already sends requests, logs and exceptions to Application Insights when the connection string is set. Operational events come from the browser SDK. One fewer dependency tree (it pulled in gRPC and OpenTelemetry)   |
| D8  | zod runs in "jitless" mode in the browser (`apps/web/src/lib/zodSetup.ts`)                         | zod 4 otherwise compiles parsers with `new Function`, which the content security policy forbids; even its probe is reported as a violation, and CSP violations fail the end-to-end tests                                                  |
| D9  | Recharts is kept for the trend chart                                                               | Named in the spec (Compare screen)                                                                                                                                                                                                        |

## Repository and CI/CD

| #   | Decision                                                                                                                                                         | Reason                                                                                                                                                                                                                           |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D10 | Workflows: `ci.yml`, `deploy-dev.yml`, `deploy-prod.yml` and a reusable `deploy.yml`                                                                             | The CI/CD table in the spec names `ci`, `deploy-dev` and `deploy-prod`; the repository layout sketch names `deploy-web` and `deploy-api`. Followed the table. The deploy workflows call CI first and deploy that run's artefacts |
| D11 | Terraform lives in `infra/`                                                                                                                                      | This session had no access to `statedge-infra`. Move `infra/modules/stride` and `infra/environments/*` there unchanged                                                                                                           |
| D12 | Separate web builds per environment (`dist-dev`, `dist-prod`) in one CI run                                                                                      | Vite bakes public settings into the bundle. Both are built and tested from the same commit, then each deploy takes its own                                                                                                       |
| D13 | Public web settings are committed in `apps/web/.env.dev` and `.env.prod`, with `REPLACE_ME` placeholders until the tenants exist                                 | None of them is a secret. The deploy workflow refuses placeholders and any test-only switch (`VITE_FAKE_AUTH`, `VITE_E2E`, dev pages)                                                                                            |
| D14 | `staticwebapp.config.json` is generated per build                                                                                                                | The content security policy names exactly that build's API, sign-in and telemetry origins                                                                                                                                        |
| D15 | The API build bakes the commit into the bundle, and the deploy health check waits for `/v1/health` to report it                                                  | Confirms the new build is the one answering, not just that something answers                                                                                                                                                     |
| D16 | The OWASP ZAP baseline scan of dev does not fail the deploy yet (`fail_action: false`); its report is kept as an artefact                                        | Its first findings need triage (rules file) before it can gate; the spec asks for the scan before the pilot                                                                                                                      |
| D17 | The Static Web App is deployed with its deployment token as a GitHub environment secret, written by Terraform; the pipeline identity gets no Static Web App role | The spec lists both; the token is the one secret the platform requires, so the extra role is not needed                                                                                                                          |

## Infrastructure

| #   | Decision                                                                                                                                              | Reason                                                                                                                                                                        |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D18 | The free-offer database is created once with `az sql db create --use-free-limit` and adopted by an import block                                       | The azurerm provider has no free-offer arguments; this is the spec's fallback                                                                                                 |
| D19 | The deploy identity is the SQL server's Entra administrator and runs migrations; staff get the API's least-privilege rights through `SQL_STAFF_USERS` | Migrations need DDL rights; nobody else needs `db_owner`                                                                                                                      |
| D20 | Platform CORS on the Function App is left empty; the API applies `ALLOWED_ORIGINS` itself                                                             | The spec asks for both. Having both duplicates the `Access-Control-Allow-Origin` header and breaks browsers; app-level CORS also covers error responses and local development |
| D21 | The Static Web App is named `stapp-stride-<env>-weu`                                                                                                  | It is in West Europe, not South Africa North                                                                                                                                  |
| D22 | The uptime check on `/v1/health` is a free external monitor set up by hand (see the runbook)                                                          | Application Insights availability tests are billed per run                                                                                                                    |
| D23 | Log Analytics cap alert is a scheduled query rule                                                                                                     | There is no metric for "cap reached". It costs cents a month                                                                                                                  |

## API

| #   | Decision                                                                                                                      | Reason                                                                                                                                                         |
| --- | ----------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D24 | Added `GET /v1/org/audit` (admin)                                                                                             | The spec asks to expose the audit log to admins in settings but lists no endpoint                                                                              |
| D25 | Added `DELETE /v1/org/invites/{id}` (admin)                                                                                   | Pending invites use a seat for seven days; an admin needs to withdraw a mistaken one                                                                           |
| D26 | `GET /v1/me` is guarded at "coach" level                                                                                      | The spec says "Token". Same behaviour: a valid token without a coach record gets `403 not_enrolled`                                                            |
| D27 | Creating an invite or a share link always answers `201`; creating a new share link replaces the report's previous public copy | Both return a token once; a repeat cannot return the same token because only its hash is stored                                                                |
| D28 | A wrong `Content-Type` answers `400 validation`                                                                               | The error table has no code for an unsupported media type                                                                                                      |
| D29 | The API validates every JSON response against its schema and drops unknown fields                                             | Catches bugs, and stops a stray column from leaking into a response                                                                                            |
| D30 | Problem `type` is `urn:statedge:stride:problem:<code>`                                                                        | Stable without depending on an unconfirmed hostname                                                                                                            |
| D31 | The web app never sends `q` to `GET /v1/athletes`; it filters its cached list on the phone                                    | A search term is a name, and the privacy checklist forbids names in URLs. The parameter stays in the API because the spec defines it                           |
| D32 | The Functions host's extended HTTP collection is off (`host.json`)                                                            | Keeps request URLs, including share tokens in `/v1/public/reports/{token}`, out of request telemetry. Our own log line carries route, status, duration and ids |
| D33 | `coaches.last_seen_at` is written at most every five minutes per coach                                                        | Keeps writes off the free database                                                                                                                             |
| D34 | Seats used are active coaches plus pending, unexpired invites                                                                 | As the onboarding section says                                                                                                                                 |
| D35 | The OpenAPI document is OpenAPI 3.1, committed at `apps/api/openapi.json` and checked by a contract test                      | Request schemas are converted as input and responses as output, so shared components appear as `X` and `XInput`                                                |

## Analysis results and reports

| #   | Decision                                                                                                                                                                | Reason                                                                                                         |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| D41 | Metric reasons are codes (`few_cycles`, `gate:camera_stable`, …), not sentences                                                                                         | The viewer, the PDF and a later Afrikaans dictionary all read the same strings                                 |
| D42 | Gate checks carry `level` (pass, warn, fail) as well as `ok`                                                                                                            | Warnings must be visible without failing the gate                                                              |
| D43 | `MetricResult.secondary` holds vertical oscillation in centimetres                                                                                                      | Its primary value is a share of leg length; centimetres need calibration                                       |
| D44 | `AnalysisResult` adds `mode`, `timebase`, `frameStep` and `keyFrames`, and `calibration` may be null                                                                    | Needed to re-run and to explain a stored result                                                                |
| D45 | `ReportSnapshot.analyses[].hidden` is a list of `{ id, reasons }` instead of `hiddenReasons: string[]`; the session block adds `footwear`; comparison caveats are codes | The PDF lists each hidden metric with its reason in the coach's language, and the athlete block shows footwear |
| D46 | The shared copy of a report always uses first name and last initial, set by the API from the athlete record                                                             | The client's choice of name style applies to the PDF only                                                      |

## Capture to result (M3)

| #   | Decision                                                                                                                                                                                                                                                                                                  | Reason                                                                                                                                                                              |
| --- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D53 | A finished result that passes the gate, or passes with conditions, is kept on the phone (IndexedDB `results`, with gzipped keypoints and the key frames) as soon as the job ends, before any save. A failed result is kept in memory only                                                                 | The spec keeps the job result in memory until saved. An analysis takes minutes and phones end background tabs; losing it would mean filming again. Sign-out clears it with the rest |
| D54 | Clip copies go to OPFS (`createWritable`, else a worker with a synchronous access handle), else to IndexedDB, else none. On app start, copies older than the organisation's retention period (counted from import) are removed; the clip record stays so that a result can offer "Pick the original clip" | As the local clip library section, with its fallbacks in that order                                                                                                                 |
| D55 | The fingerprint is SHA-256 over the first MiB of the file followed by its size as an unsigned 64-bit big-endian integer                                                                                                                                                                                   | The spec says "the first megabyte plus size" without the byte layout                                                                                                                |
| D56 | The athletes picked on `/sessions/new` are kept on the phone and offered first on import; they are not sent                                                                                                                                                                                               | The API has no link between a session and athletes: athletes join a session through its clips                                                                                       |
| D57 | Calibration happens on `/import`, straight after the clips are chosen; `/analyse/:clipId` picks one of the session's calibrations and draws the athlete box                                                                                                                                               | The calibration clip's copy is dropped after calibration (spec), so the frame must be tapped while the file is still open. One calibration serves every run of the set-up           |
| D58 | The analysis starts at the frame the athlete box was drawn on; the coach moves to a frame where the whole athlete is in view                                                                                                                                                                              | The box seeds the tracking; on most clips the athlete enters after the first frame                                                                                                  |
| D59 | The device check uses the gate's clip-level checks in sprint mode. The coach says the rate the clip was filmed at, as on import. A file re-timed for playback is Conditional (reason `retimed_file`) because its real frame timing cannot be checked                                                      | A re-timed slow-motion file and normal video look the same from their timestamps                                                                                                    |
| D60 | Device tiers are labelled "A: tested, recommended", "B: works, with limits", "C: not recommended"                                                                                                                                                                                                         | The spec defines the A, B, C column but not its meaning                                                                                                                             |
| D61 | Resumable jobs (checkpoints every 100 frames) are not built. A job pauses while Stride is hidden, says so, and keeps the screen awake                                                                                                                                                                     | Marked "should have" in the offline section and listed under Stretch in the milestones                                                                                              |
| D62 | Test builds ship the recorded keypoint fixtures at `/e2e-fixtures/` and precache them; the nightly real-model check (`nightly.yml`) runs the full model on the CPU delegate on the synthetic stick-figure clip                                                                                            | No video of a real person may be committed. The nightly check proves the model, its WASM runtime and the worker load and run, not what they measure                                 |
| D63 | Key frames lower the JPEG quality in steps of 0.1 (to 0.4 at most) when needed to stay under 300 KB                                                                                                                                                                                                       | Keeps the spec's size limit for busy frames                                                                                                                                         |
| D64 | The capture guide text (checklist and run sheet) is written for the MVP. Passes in both directions are suggested "if there is time"                                                                                                                                                                       | The spec names the page but not its text; open question 5 is still open                                                                                                             |
| D65 | Confidence badges are a neutral three-dot scale with the level in words; no traffic-light colours                                                                                                                                                                                                         | Colour is never the only signal, and nothing may read as a good or bad judgement                                                                                                    |
| D66 | The viewer's angle read-outs show knee bend, hip flexion and shin angle for both sides and trunk lean, from the raw landmarks of the frame shown                                                                                                                                                          | They describe the skeleton drawn on that frame                                                                                                                                      |
| D67 | The query cache keeps unused queries for as long as the persister keeps them (7 days)                                                                                                                                                                                                                     | With TanStack's default of 5 minutes, data not on screen dropped out of the persisted cache and was missing after an offline restart                                                |

## Measured in the spike (M0)

See `docs/spike-report.md` for the numbers behind these provisional choices: WebCodecs with the video-element fallback, a module worker, the full model with the GPU delegate and CPU fallback, a 256 by 144 stability signature, and low-pass cut-offs of 16 Hz (distance) and 25 Hz (sprint). The on-device measurements on the S23 Ultra are still to be made.
